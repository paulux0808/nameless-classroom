# 30_HISTORICAL_PRESENTATION.md

# HISTORICAL PRESENTATION SPECIFICATION

이 문서는 NAMELESS Ⅱ에서 실제 역사 인물, 실제 사건, 실제 날짜, 실제 프로젝트와 게임을 위해 창작·압축·재구성된 장면을 어떻게 구분하고 제시할지를 정의한다.

이 게임은 역사 다큐멘터리가 아니다.

동시에 실제 인물과 실제 결과를 사용하면서 허구 장면을 실제 기록처럼 오인시키면 안 된다.

따라서 모든 역사 표현은 다음 세 층을 구분한다.

```text
HISTORICAL FACT
DRAMATIZED / COMPRESSED HISTORY
GAME FICTION
```

이 구분은 Final Archive, 인물 프로필, ending 이후 역사 설명, 외부 소개문을 설계할 때 특히 중요하다.

---

# 1. 핵심 원칙

게임의 정서적 힘을 위해 실제 역사를 사용한다.

그러나:

```text
실제 이름
+
실제 날짜
+
실제 프로젝트
```

가 등장한다는 이유로 게임의 모든 대화와 사건을 실제 기록처럼 제시하지 않는다.

---

# 2. 세 가지 역사 레이어

## HISTORICAL FACT

신뢰 가능한 역사적 기록에 근거해 직접 제시할 수 있는 정보.

예:

• 실제 인물 이름
• 주요 역할
• Manhattan Project / Los Alamos와의 관계
• Hiroshima / Nagasaki 날짜
• Little Boy / Fat Man
• 전쟁 종결 맥락

---

# 3. DRAMATIZED / COMPRESSED HISTORY

실제 인물·조직·시대·업무 관계를 바탕으로 게임 플레이를 위해 시간, 장소, 만남, 순서를 압축하거나 합성한 것.

예:

• 과학자들이 한 Director에게 차례로 퍼즐 형태의 문서를 제출
• 여러 실제 연구 활동을 한 챕터의 대표적 검토 상황으로 압축
• 여덟 인물이 한 최종 검토 공간에 모이는 장면
• 동일 시설 구조 안에서 실제보다 단순화된 업무 동선

---

# 4. GAME FICTION

게임을 위해 창작한 사건.

예:

• 특정 계산 카드 오류
• 특정 calibration mismatch
• 특정 사고 보고서 오류
• CH5의 정확한 대립 대사
• CH8 final report 오류의 조합
• CH10 전화 수화기 투척
• 소포 안 photo/medal/postcard 배치
• 게임-specific distinguished service token
• `SUCCESS?` 시스템 이상 연출

---

# 5. 게임 안에서 매번 라벨하지 않는다

각 대사 옆에:

```text
[허구]
[역사 사실]
```

을 붙이지 않는다.

몰입을 깨기 때문.

구분은 Final Archive / Credits / Historical Notes 등 적절한 후반 정보에서 제공한다.

---

# 6. 플레이 중 표현 방식

플레이 중에는 자연스러운 장면으로 보여준다.

다만 허구를 사실처럼 단정하는 후속 역사 설명을 피한다.

---

# 7. Final Archive의 역할

Final Archive는:

```text
게임 속 인물
→ 실제 역사 인물
```

의 연결을 명확히 한다.

하지만 게임 속 모든 대사를 실제 발언처럼 인증하지 않는다.

---

# 8. Historical Note

필요하면 Final Archive 또는 ending 이후 짧은 note:

```text
본 작품은 실제 역사와 인물을 바탕으로 한 극화된 창작물입니다.
일부 만남, 대화, 업무 과정과 사건의 세부는 게임을 위해 압축·재구성되었습니다.
```

정도의 명시가 적합하다.

---

# 9. 과도한 면책문 금지

게임 시작부터 긴 법적/역사적 disclaimer를 보여주지 않는다.

정체 reveal 전에 실명/프로젝트명을 언급하는 disclaimer도 스포일러가 될 수 있다.

---
