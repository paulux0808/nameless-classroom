## 0. 먼저 알아야 할 기술 제약

### 배율이 아니라 실치수를 적는다

엔진이 바운딩박스를 재서 맞춘다. 매니페스트에 `scale` 대신 **실제 크기(m)** 를 적으면
어떤 모델로 바꿔 끼워도 배치가 무너지지 않는다.

```js
{ id:"desk", path:"1943_steel_desk/desk.gltf",
  pos:[0,0,0.5], rot:[0,Math.PI,0], fitHeight:0.76 }
```

| 필드 | 뜻 |
|---|---|
| `fitHeight` | 이 높이(m)가 되도록 균일 배율 |
| `fitWidth` | 폭 기준. `fitHeight`와 같이 주면 작은 쪽 채택 |
| `align` | `"floor"`(기본) 바닥에 앉힘 / `"center"` / `"none"` |
| `center` | `false` 면 모델 원점을 그대로 존중 |
| `debug` | 콘솔에 원본 크기와 적용 배율 출력 |

브라우저 콘솔에서 `N2Engine._measure()` 를 부르면 실제로 어떤 크기로 앉았는지 나온다.
에셋을 갈아 끼운 뒤 이걸로 확인한다.

### 포맷

- **glTF 2.0 (`.gltf` + `.bin` + textures) 또는 `.glb`** — 현재 로더가 이것만 읽는다.
- 텍스처는 **1K(1024²)** 로 충분하다. 2K 이상은 모바일에서 메모리를 잡아먹는다.
- PBR 채널은 `diff` / `nor_gl` / `arm`(AO·Rough·Metal 합본) 구성이면 그대로 붙는다.
- **Y-up, 미터 단위, 원점은 바닥 중앙**이 가장 손이 덜 간다. 아니어도 엔진이 맞추지만,
  회전 축이 어긋난 모델은 `rot`으로 일일이 보정해야 해서 번거롭다.

### 예산

한 챕터가 한 번에 들고 있는 것 기준이다. 챕터 단위로 씬을 새로 만들기 때문에
10챕터 전체를 동시에 로드하지 않는다.

| 항목 | 목표 |
|---|---|
| 챕터당 GLTF 합계 | 25MB 이하 |
| 챕터당 드로우콜 | 300 이하 |
| 텍스처 세트 | 챕터당 12세트 이하 |
| NPC 1인 | 40k 삼각형 이하 |

### 라이선스

`assets/vendor/`, `assets/models/` 에 넣는 것은 전부 출처와 라이선스를 남긴다.
CC0 (Poly Haven, ambientCG) 가 가장 안전하다. CC-BY 는 크레딧 표기 의무가 있으니
`docs/CREDITS.md` 에 같이 적는다. **Sketchfab의 "무료"는 대부분 CC-BY이고
일부는 재배포 금지다** — 다운로드 전에 확인한다.

## 3. NPC — 가장 큰 작업

**8명이 이름으로 구분되고, 반려를 받아들이는 태도가 각자 다르다.**
`02_DIALOGUE_NPC.md` 는 제스처를 8계층으로 규정한다:

```
BASE POSTURE / GAZE / HEAD / TORSO / ARM / HAND / OBJECT HANDLING / REACTION
```

Base posture 후보 8종: `RELAXED_STAND` `FORMAL_STAND` `WORK_STAND` `LEAN_LIGHT`
`SEATED_WORK` `SEATED_REST` `BOARD_STAND` `REPORT_HOLD`

### 필요한 것

| 항목 | 수량 | 비고 |
|---|---:|---|
| 리깅된 남성 캐릭터 | 8 | 1940년대 복장 — 셔츠, 조끼, 넥타이, 랩코트 |
| 배경 연구자 | 4~5 | CH2 칠판 앞 군중용. 실루엣만 달라도 됨 |
| 공용 애니메이션 | — | idle, 걷기, 서류 건네기/받기, 고개 끄덕임/젓기, 팔짱, 돌아서기 |

### 현실적인 접근

- **Mixamo** 는 무료 + 자동 리깅 + 애니메이션이 풍부하지만 어댑터 계정이 필요하고
  복장이 현대적이다. 옷만 교체하거나 텍스처를 시대에 맞게 바꾸는 편이 빠르다.
- 8명을 완전히 다른 모델로 만들 필요는 없다. **체형 2~3종 × 복장·머리색 변형**이면
  스펙이 요구하는 "이름으로 구분된다"를 충족한다.
- 얼굴 디테일보다 **자세와 실루엣**이 중요하다. 대사창에 이름이 뜨고,
  플레이어는 대부분 중거리에서 본다.

## 4. 문서 — 3D가 아니라 텍스처/HTML

`04_DOCUMENT_OBJECTS.md`

문서는 모델이 아니라 **데이터**다. 현재 엔진은 문서를 HTML 카드로 띄운다
(`chapters/ch01.js` 의 `docs` 참조). 3D 모델이 필요한 건 책상 위에 놓인
**문서 더미의 겉모습**뿐이다.

준비할 것:

- 종이 텍스처 (타자기 인쇄, 등사, 청사진) — 평면 텍스처로 충분
- 문서 바인더 / 폴더 / 클립보드 모델
- **도장 2종** (APPROVED / REJECTED) + 잉크패드 ★ 게임의 상징
- 스탬프 자국 텍스처 (알파 포함)

주의: `04 §11 정답 색칠 금지` — 정답에 해당하는 값을 시각적으로 강조하면 안 된다.
`04 §23 무기 관련 직접 표현` 과 `§21 개발용 내부 이름과 표시 문자열 분리` 도 지킨다.

## 6. CH9 영상 — 라이선스 주의

`08_HISTORICAL_PRESENTATION §32~35`

스펙이 **실제 아카이브 영상을 요구하지 않는다.** 명시적으로 허용한다:

> B-29, route, release, flash, mushroom cloud를 **합성/재구성**할 수 있음.
> 모든 frame이 실제 기록 영상이라는 인상을 주면 안 된다.

즉 실사 필름을 구할 필요가 없다. 재구성 영상으로 만들면 라이선스 문제가 사라지고
스펙도 더 잘 지킨다. 필요한 것:

- B-29 모델 (실루엣 수준이면 충분 — 대부분 역광/구름 속)
- 구름·고도 배경
- 섬광·버섯구름은 셰이더/파티클 또는 사전 렌더링 영상

`§35`: 민간인 피해를 직접 전시하지 않는다. 동시에 결과의 규모를 회피하지도 않는다.
