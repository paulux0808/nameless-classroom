# Stage 1 재설계 (2026-09-30)

요청: **스토리는 그대로 두고**, 퍼즐·구조·배치·그래픽·대사를 전부 개선한다. 기발한 퍼즐은 남긴다.
이 문서는 재설계의 기준이다. 구현이 이 문서와 달라지면 문서를 먼저 고친다.

> 정답은 여기에 적지 않는다(`stage1/tests/answers.mjs` 와 같은 원칙). 퍼즐의 *방식*만 적는다.

## 원칙

1. **이야기는 고정**이다: 유언장(인트로), 일기 9편의 본문, 여덟 조각의 제목·시대, 조립 순서, 최종 이름, 엔딩 글과 영상,
   뒷문 코드와 스테이지 2 입구. `data.js` 는 글자 그대로 둔다(내용 잠금 테스트가 지킨다).
2. **기발한 퍼즐의 핵심 논리는 그대로** 둔다. 바꾸는 것은 *다루는 방식*과 *피드백*이다.
3. **퍼즐은 교실 안에서 푼다.** 챕터마다 다른 동사(맞추다·찍다·되감다…)와 다른 장소를 준다. 단말기에 정답을 치는 일은
   "머릿속으로 추리한 말"을 내놓는 퍼즐(3·5·6·7·8장)에만 남긴다.
4. **모든 행동에 피드백**이 있다. 막히면 감독교사에게 3단계 힌트를 청할 수 있다.
5. **기억이 돌아올수록 교실이 채워진다.** 조각을 칠판에 붙일 때마다 방에 물건이 하나 생긴다(이름 없는 교실 → 이름을 되찾는 교실).
6. **모델은 그대로.** 새 상호작용은 정규화된 답 문자열로 `M.answer()` 를 부른다. 봉인 해시·저장 형식(옛 저장 포함)이 호환된다.

## 챕터별 설계

| 장 | 이야기 조각 | 퍼즐 핵심(유지) | 방식 (2026-10-01 리뉴얼 반영) | 장소 |
|---|---|---|---|---|
| 1 | 태어난 날 | 일기의 빈칸 날짜를 다른 단서에서 계산 | **날짜 도장**: 일기 빈칸과 같은 모양의 바퀴 5개를 맞춰 찍는다. 찍는 것이 곧 제출이다(컴퓨터는 꺼져 있다) | 교탁 |
| 2 | 별명 | 기호 다섯과 인물 다섯을 짝짓고 남는 한 사람을 찾는 소거 | **액자 뒷면**: 액자를 눌러 들면 뒷판에 글자 쪽지가 있다. 종이의 기호 순서대로, 설명판 *본문*에서 찾은 주인 액자의 쪽지를 이어 읽는다. 답은 컴퓨터 | 오른쪽 벽 액자·칠판 |
| 3 | 조정부 | 포지션이 정확히 아홉 개인 종목 찾기 | **명단 읽기**: 클립보드는 명단만 보여 준다. 종목 자료의 포지션을 *세어* 가린다(‘한 팀 인원’이 아홉인 종목이 둘이라는 함정). 답은 컴퓨터 | 앞쪽 왼편 스포츠 코너 |
| 4 | 우주의 시작 | 시간을 거꾸로 | **신호 테이프**: 별의 깜빡임(모스 부호)을 *되감으며* 기록장에 적고, 벽의 해독표로 읽는다. 재생하면 뜻 없는 글자가 된다. 답은 컴퓨터 | AV 카트(TV+VCR)·카트 옆 벽 |
| 5 | 로마 | 알파벳 격자 + 상표 이니셜 길 찾기 | 지도에 **연필 메모**(칸에 글자 적기·칸에 표시). 안내 문장은 스스로 따라간다 | 칠판·자료 |
| 6 | 책 제목 | 자막이 곧 규칙인 훼손된 영상 | 영상을 **같은 TV**에서 튼다. 암호문 글자를 눌러 지우는 메모 기능 | AV 카트 |
| 7 | 한국 | 사전의 첫 뜻풀이 이니셜 | 쪽지의 붉은 낱말을 **교탁 위 한영사전**(방 안, 봉인 데이터)에서 찾아 영어 첫 뜻을 적어 둔다. 머리글자는 스스로 모은다 | 교탁·자료 |
| 8 | 근섬유 | 이동 횟수×2초 + 대기시간 계산 | 근섬유 키보드 설명서를 **읽기 좋게 정리**하고 계산 메모 칸을 준다 | 커튼 앞 |

- **탐색 단계**(어디에 다음 편지가 있는지 단서로 찾기)와 **편지 → 칠판 붙이기**는 그대로 둔다. 다만 단서를 감독교사가 읽어 준다.
- 교탁 컴퓨터는 **답을 넣어야 할 때에만 켜진다**(2~8장 읽기 단계, 탑 완성 뒤 이름 입력). 1장은 날짜 도장이 곧 제출이라 꺼져 있고,
  탐색·편지 단계에도 꺼져 있다. 꺼진 컴퓨터는 눌러도 열리지 않고, 감독교사가 이유와 지금 할 일을 말해 준다.
- 마지막 **기억 조립**과 이름 입력, 뒷문은 그대로다.

## 감독교사(대사·힌트)

교실을 지키는 감독교사가 안내자가 된다. 답은 절대 말해 주지 않는다. 말투는 건조하고 예의 바르며 속은 따뜻하다.

- 장면: 입장, 첫 일기, 장 시작, 오답, 정답과 단서 낭독, 편지 발견, 조각 붙임, 오래 막혔을 때, 엔딩.
- **힌트 3단계**(방향 → 핵심 → 거의 정답). 장마다 따로 세고 저장한다. 3단계 문구는 봉인(`U()`)해서 저장소를 열어도 바로 읽히지 않는다.
- 자막 말풍선: 하단 중앙, 한 글자씩 나타나고, 누르면 넘어간다. 감독교사는 말하는 동안 고개와 손을 움직인다.

## 배치와 밀도

- 새 장치: 날짜 도장, AV 카트, 명단 클립보드·노·페넌트(스포츠 코너), 표식 카드 서랍(액자 아래).
- **기억 소품 8개**가 조각마다 생긴다(별 모빌, 낙서, 지팡이, 별자리 포스터, 메달, 책, 소형 태극기, 스탠드 조명).
- 동선: 시작 위치에서 첫 일기가 곧장 보이고, 장마다 목표 장소가 서로 다른 구역이 되도록 배치를 정리한다.
- 생활감 소품(가방·우산·낙서한 책상·칠판 잔글씨)을 더한다.

## 그래픽·연출

- 카툰 렌더링 유지. 감독교사 얼굴을 다시 만든다(흰자·눈동자 하이라이트·눈썹·입 모양 세 가지).
- 리빌은 눌렸다 튀는 동작(스쿼시&스트레치), 정답에는 분필 가루 이펙트, 조각 붙임에는 칠판으로 날아가는 궤적.
- 엔딩은 기존 글·영상을 살린 채 진입 연출만 다듬는다.

## 구현 순서(각 단계가 끝날 때마다 게임은 끝까지 플레이 가능해야 한다)

1. 대사·힌트·목표 안내(`lines.js`, 자막 UI, 힌트 버튼, 모델 상태)
2. 퍼즐 틀(`puzzles.js` 순수 로직) + 1·2장
3. 3·4장(스포츠 코너, AV 카트)
4. 5~8장 메모 도구와 자료 정리
5. 기억 소품·배치·밀도
6. 그래픽·연출
7. 테스트·e2e 갱신·문서·PR(승인 전에는 메인에 합치지 않는다)

## 상태 확장(저장 호환)

`hints`(장별 사용 단계), `pz`(퍼즐별 진행), `said`(한 번만 하는 대사 기록)를 `S` 에 더한다.
`storage.fresh()` 가 기본값을 주고, 옛 저장에는 이 값이 없어도 그대로 읽힌다.

### 계획에서 달라진 점 (하지 않은 것)

- **표식 카드 서랍**: 카드는 3D 서랍이 아니라 패널 안의 트레이에 둔다.
- **생활감 소품**(가방·우산·낙서한 책상·칠판 잔글씨)을 새로 더하지는 않았다. 기억 소품 8개와 스포츠 코너·AV 카트가 밀도를 채운다.
- **스쿼시&스트레치·분필 가루**: 편지·소품은 `outBack` 으로 튀어 오르고 반짝이 입자를 쓴다. 분필 가루 모양의 이펙트와 엄밀한 스쿼시&스트레치는 만들지 않았다.
- **엔딩**: 기존 글·영상·문·빛 연출을 그대로 쓴다.
- 8장은 새 조작 대신 표와 설명서 정리에 그쳤다(퍼즐 핵심이 계산이라 도구를 더 얹지 않았다).

### 검증하는 법

```sh
npm run test:stage1          # 단위·구조 테스트 (스포일러 린트 포함)
npm run e2e:stage1           # 8챕터~엔딩~뒷문~이어하기 (기존 정답 경로)
npm run e2e:stage1:puzzles   # 새 조작 하나하나 + 모바일 가로 화면
```

성능(정지 화면 한 프레임, 그림자 갱신 제외)은 재설계 전과 거의 같다. 시작 시점 그리기 호출 233→268, 삼각형 55.6만→57.2만이고
방 안쪽·창·액자 쪽 시점은 호출 ±5 이내다(스포츠 코너·AV 카트·기억 소품이 보이는 시점에서만 늘어난다).

브라우저 검증은 소프트웨어 렌더링(SwiftShader)으로 돌렸다. 실제 GPU·실제 터치 기기에서의 프레임 속도와 손맛은 확인하지 못했다.

## 리뉴얼 (2026-10-01): 퀴즈는 퀴즈답게

재설계 뒤 플레이해 보니 아쉬운 곳이 있었다. 퀴즈가 퀴즈 같지 않았고(닿으면 곧바로 맞고 틀림이 나오거나, 정답 글자가 화면에 그냥 나온다),
조각을 쌓는 화면은 조각마다 크기가 달랐으며 중간에 쌓아 볼 수도 없었다. 이야기는 그대로 두고 *방식*만 다시 정한다.

### 공통 규칙 (모든 장치·퍼즐이 따른다)

1. **도구는 기록만 한다.** 맞고 틀림을 알려 주는 곳은 정해진 *제출*(탑의 ‘완성’, 컴퓨터의 입력) 하나뿐이다. 닿자마자 판정하는 장치를 두지 않는다.
2. **정답은 유도해서 얻는다.** 화면에 정답 글자가 그냥 나오지 않는다. 관찰 → 규칙 이해 → 대조·계산 → 입력의 순서를 지킨다.
3. **같은 종류의 물건은 같은 규격이다.** 탑의 블록은 모두 같은 크기·같은 틀(그림·제목·연도)이다.
4. **컴퓨터는 입력할 때만 켜진다.** 현장 장치(탑·카트·표식)는 기록 도구이고, 말로 내놓는 답은 컴퓨터에 넣는다.
5. **판정이 없는 동안에는 감독교사도 조용하다.** 순서가 맞아도, 기록이 맞아도 제출하기 전에는 아무 말도 하지 않는다.
6. **모양은 한 벌이다.** 종이(잉크 #1b2640·종이 #f2efe0·붉은 줄 #c2382b) 위에 나무(도구)·놋쇠(제출)·노란 후광(조사 가능)을 쓴다.
   단추 크기와 표기(●짧게 ▬길게 ｜쉼 / ▲▼ / 완성)는 패널마다 같게 한다.
7. **정답은 저장소에 평문으로 없다.** 풀이 검증은 테스트가 봉인된 정답에서 거꾸로 유도해 본다(한 가지 길로만 풀리는지, 지름길이 없는지).

### 기억의 탑 (구현됨)

- 교단 위 받침대에 조각을 얻을 때마다 **같은 규격의 나무 블록**이 맨 위에 내려앉는다(`props/tower.js`). 블록마다 그림(별 모빌·낙서·지팡이…)·제목·연도.
- 눌러 열면 쌓기 패널(`tower.js`): 블록을 **눌러 고르고 ▲▼ · 끌기 · 키보드(↑↓)** 로 옮긴다. 조각이 8개 모이기 전에도, 언제든 쌓아 볼 수 있다.
  곁에 마지막 일기(여덟 조각이 모이면 읽힌다)를 두고 순서를 맞춘다. **순서가 맞아도 ‘완성’을 누르기 전에는 확정도 안내도 없다.**
- ‘완성’은 **한 번만 판정**한다. 틀리면 탑이 우르르 무너졌다가 지금 순서대로 다시 쌓이고(어디가 틀렸는지는 알려 주지 않는다), 맞으면 블록 앞면에
  **이름의 뼈대(모음이 지워진 글자)** 가 블록을 가로질러 이어서 새겨지며 따뜻하게 빛난다.
- 배열은 **위에서 아래로**(마지막 일기의 목록과 같은 방향). 저장은 `S.tower`(추가 필드, 옛 저장은 조립 배열을 가져온다).
- **이름은 스스로 말한다.** 탑이 완성되면 컴퓨터가 켜지고, 새겨진 뼈대를 보며 이름을 입력한다. 이름 전체·성+이름·성만 모두 받는다(`finalAccepts`).
  뼈대는 힌트 3단계에도 쓴다.
- 옛 조립 화면(조각 크기가 제각각이던 것)과 `ensureStack`/`swapStack`/`bandOf` 는 지웠다.

### 장별 리뉴얼 (구현됨)

**4장 신호 테이프** (`puzzles.js` 신호 논리, `stations.js` VCR, `tools.js` 기록장·해독표, `props/stations.js` 해독표 카드)

- 4번 테이프는 한 점으로 무너지는 별의 **깜빡임(모스 부호)** 이다. 점 1칸·선 3칸·글자 안 쉼 1칸·글자 사이 3칸·낱말 사이 7칸(칸 = 0.34초), 앞뒤는 어둡다.
- **화면을 보며 되감으면(◀◀) 신호가 바른 차례로 흐르고, 그냥 재생(▶)하면 시간이 거꾸로 흘러** 모든 부호가 글자로 읽히긴 하지만 뜻 없는 글자가 된다. 일기의 “시간만 거꾸로”를 그대로 해야 읽힌다.
- VCR 패널: 별빛(켜질 때 고리가 번진다)과, 지나온 깜빡임이 흘러가는 **기록 띠**(속도와 상관없이 폭이 같다), 속도(½·1·2)·소리, 조그.
  **기록장**은 ●짧게 ▬길게 ｜쉼(한 번은 글자 사이, 두 번은 낱말 사이)만 적고 풀이하지 않는다. 물리 키보드 `.` `-` `/` 도 된다. 정답 키패드는 패널에 없다.
- 4장이 시작되면 카트 옆 벽(창 아래)에 **해독표**가 붙는다(눌러 읽는다). 컴퓨터의 ‘신호 기록’ 탭에서 적어 둔 부호를 보며 답한다.
- 풀이 검증: 이상적인 관찰자가 되감기로 보면 낱말(3+4글자), 재생으로 보면 `WANV WIV` 꼴의 뜻 없는 글자. 통째로 뒤집기·낱말 순서 바꾸기·글자별 뒤집기 모두 낱말이 되지 않는다.

**2장 액자 뒷면** (`puzzles.js`, `stations.js` ST.showFrameBack, `screens.js` 종이 한 장)

- 일기의 “액자를 더 자세히 보세요!”를 그대로 쓴다. 액자를 누르면 벽에서 살짝 들리고(3D) 뒷판의 글자 쪽지가 보인다. 액자는 이제 돌지 않는다.
- ‘종이 한 장’은 기호 다섯 개를 **위에서 아래로** 번호 순서대로 적은 순서표다. 각 기호의 주인(설명판 *본문*에서 찾는다)의 뒷면 글자를 그 순서대로 이으면 낱말이 된다.
  기호 없는 여섯째 액자에도 쪽지가 있어 쪽지가 없는 것으로 들통나지 않는다.
- 설명판의 ‘핵심’ 줄(떨어지는 사과·원주율 등)은 화면(패널·방 안 인쇄물)에서 지웠다. 뉴턴 설명판에는 사과 일화 한 문장을 더했다(`data.js` 잠금 해시 갱신).
- 풀이 검증: 설명판 본문의 열쇠말만으로 기호↔인물 완전 짝짓기가 **정확히 하나**(경우의 수 1)이고 남는 인물이 여섯째, 이어 읽기 = 정답, 다른 차례·기호 없는 쪽지 끼우기는 정답이 아님.

**3장 명단 읽기** (`stations.js` ST.showRoster)

- 이름을 자리에 앉혀 주고 ‘딱 맞음’을 알려 주던 것을 없앴다. 클립보드는 명단(1~9번, 마지막 ‘나’)과 접어 둔 운동경기 자료만 보여 준다.
- 종목은 포지션을 세어 가린다. 인원 표기가 아홉인 종목이 둘(야구는 지명타자로 포지션이 열 개)이라는 함정과 체중 규정 단서는 그대로다.

**5장 지도** (`tools.js` T.map): 자동 ‘따라가기’를 없앴다. 칸에 알파벳을 적는 모드와 칸을 연필로 표시하는 모드가 있고 저장된다.

**7장 방 안 사전** (`dict.js`, `props/desk.js` P.dictionary, `screens.js` SC.showDict): 밖의 사전 링크를 없애고 교탁 위에 한영사전을 두었다.
쪽지의 열다섯 낱말(쪽지에 적힌 모양 그대로)과 상관없는 낱말 스무 개를 가나다순으로 싣고, 영어 뜻은 많이 쓰이는 순서대로 적어 맨 앞이 대표 뜻이다(봉인 U).
쪽지 메모 칸은 영어 뜻만 적어 두고 머리글자는 스스로 모은다. 테스트가 첫 뜻 머리글자 이으면 정답·다른 뜻은 정답이 아님·영어 뜻이 평문으로 없음을 지킨다.

**기록** (`model.js` tick/record, `storage.js` S.log): 장별 걸린 시간(초, 키 1~8·f)과 받은 힌트 횟수를 조용히 모아 스테이지 완료 화면의 ‘내 기록 보기’에 보여 준다.
쉬는 동안(시작 전·이름을 맞힌 뒤)에는 세지 않고, 느린 화면에서도 실제 시간으로 센다. 지인에게 플레이를 부탁했을 때 난이도를 가늠하는 자료다.

### 이번에 하지 않은 것

- 1장 도장 종이를 세 장으로 제한하기, 6·8장 손질(원작 핵심이 이미 퍼즐이라 그대로 둔다).
- 4장 해독표는 방에 처음부터 있지 않고 4장에서 붙는다(처음부터 보이면 풀이 방식이 미리 드러난다).
- 난이도는 사람이 풀어 봐야 맞춰진다. 힌트 3단계는 그대로 두었고, 기록으로 조절 여지를 남겼다.

### 플레이테스트로 난이도 맞추기

난이도는 사람이 풀어 봐야 맞춰진다. 지인(처음 하는 사람이 좋다)에게 한 번 해 달라고 하고, 끝난 뒤 스테이지 완료 화면의 **‘내 기록 보기’** 를 함께 본다.

- **오래 걸린 장**(예: 10분 넘게): 도움이 0번이면 안내가 부족한 것이고(힌트 단추를 못 찾았거나 막막함), 도움이 2~3번이면 단서 사이의 간격이 먼 것이다.
- **너무 빨리 끝난 장**(1분 안팎): 정답을 짐작으로 찍었을 수 있다. 호킹을 아는 사람은 마지막 이름을 곧바로 찍을 수 있다(막을 수 없다).
- 도움을 청한 횟수는 ‘틀린 입력’과 따로다. 틀린 입력은 세지 않는다(벌이 아니다).
