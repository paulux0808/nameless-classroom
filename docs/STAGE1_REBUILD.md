# Stage 1 재제작 (2026-09-29)

스테이지 1 "이름 없는 교실"을 처음부터 다시 만들었다. **내용(이야기·일기 8편·퍼즐 8개·정답)은 그대로**이고,
3D 교실과 화면(UI·조작)을 새로 썼다. 화면은 **카툰(셀 셰이딩 + 잉크 윤곽선)이 기본**이고, 사실적인 렌더도 남겨 두었다.

## 한 줄 요약

- **외부 3D 에셋 0개.** GLTF·모델·HDR·텍스처 이미지를 하나도 불러오지 않는다. 방의 모든 것(책걸상, 교탁,
  칠판, 사람, 커튼, 마루, 하늘, 환경 반사까지)을 코드가 만든다. (`tests/structure.test.mjs` 가 지킨다)
- **카툰 렌더링이 기본**: 3단 명암·잉크 윤곽선·조사 가능한 물건의 노란 후광. 메뉴의 "화면 스타일"에서
  카툰/사실적을 바꿀 수 있다(저장되고, 바꾸면 다시 불러온 뒤 자동으로 이어진다). 주소에 `?style=real` 을 붙여도 된다.
- 초상화 6장과 영상 2개는 **퍼즐 내용**이라 그대로 쓴다 (`portraits.js`, `assets/video-*.mp4`).
- 조작·화면은 PC(WASD·마우스·키보드 입력)와 모바일 가로(조이스틱·조사 버튼)를 함께 설계했다.

## 설계 결정

### 방은 전부 코드로, 그러나 촘촘하게
옛 방은 상자·원기둥을 쌓은 수준이라 가까이 가면 밋밋했다. 새 키트는 다음으로 밀도를 낸다.

- **둥근 상자·판·관**: 모서리를 깎은 상자(`rbox`), 상판·좌판을 둥글게 굽힌 판(`plate`), 꺾임을 필렛으로 이은
  철관(`pipe`). 책상 하나가 볼트·브래킷·고무 받침까지 갖는다.
- **캔버스 텍스처 + 범프**: 나무결(고리·섬유·기공), 회벽 얼룩, 천 올, 칠판 분필 자국을 코드로 그린다.
  범프 크기는 미터 단위다(r128 의 `bumpScale`).
- **진짜 마루판**: 판마다 색·결이 다르고 이음매가 어긋난다(`R.planks`). 교단 윗면도 같은 규칙.
- **진짜 개구부**: 벽은 창·문 구멍이 뚫린 압출체다. 햇빛이 창 모양 그대로 바닥에 떨어진다.
  **천장이 빛을 막아야** 창으로만 든다(`ceil.castShadow = true` — 빠지면 T-바 그림자가 줄무늬가 된다).
- **환경 반사(IBL)도 코드로**: `K.makeEnv` 가 방·스튜디오 조명 큐브맵을 그려 PMREM 으로 쓴다.

### 움직임
- 리빌: 물건이 호(arc)와 회전으로 치워지고(달력·인형·쪽지·소화기·시계·수학책), 교사는 관절 리그로
  일어나 걸어 비켜서고(`standAndMove`), 커튼은 천 격자가 펼쳐지며 방이 어두워진다.
- 편지: 나타날 때 커지며 떠오르고, 읽고 나면 칠판의 자기 자리로 **날아가 붙는다**. HUD 나무 조각이 튄다.
- 액자: 90° 돌 때 살짝 튕기며(outBack) 4→0 에서도 늘 같은 방향으로 이어 돈다.
- 문: 코드가 맞으면 카메라가 다가가고 문이 열리며 빛이 밀려든다 → 화이트아웃 → 완료 패널.
- 상시: 먼지, 빛줄기 맥동, 시계 초침, CRT 깜빡임, 지구본, 커튼 주름, 교사 숨쉬기·깜빡임·시선.

### 화면
- 팔레트: 칠판 초록·시험지 흰색·남색 잉크·빨간 펜·연필 노랑. **HUD 진행 표시는 최종 조립에서 쌓는 나무 조각**이다.
- 패널은 방을 가리지 않고 오른쪽에 붙는 줄 공책이다. 단말기만 CRT 장치다.
- PC 는 물리 키보드로 답을 넣고(Enter 제출), 버튼 키패드도 그대로 있다. 모바일은 조이스틱+조사 버튼.
- 폰 가로 최소 568×320 까지 확인했다(짧은 화면 규칙은 `style.css` 의 `max-height` 미디어 쿼리).

### 카툰 렌더링 (기본 화면)
- **재질**: `MeshToonMaterial` + 코드가 만든 16칸 램프(`K.toon.RAMP3`)로 빛이 3단(그림자·중간·밝음)으로 끊긴다.
  색은 채도·밝기를 살짝 올리고(`K.toon.color`), 캔버스 텍스처는 뭉개고 단계를 줄여 붓으로 칠한 듯하게 한다
  (`K.toon.toonify` — 밝기만 끊고 색조는 유지한다; 채널별로 끊으면 베이지가 분홍이 된다).
  모든 툰 재질은 셰이더 프로그램 하나를 공유하고, 굳은 하이라이트·림빛은 `onBeforeCompile` 로 얹는다.
- **빛**: 환경 반사·안개·톤매핑을 쓰지 않는다. 햇빛(그림자 있음)과 별도로 **그림자 없는 주광**을 하나 두어,
  햇빛이 닿지 않는 곳에서도 모든 물체에 밝은 면·어두운 면이 생기게 했다(`room/lighting.js` 의 `PR` 프리셋).
  하늘은 굳은 색띠·뭉게구름·겹겹 언덕으로 다시 그렸다.
- **윤곽선**(`kit/outline.js`): 뒤집은 껍질(inverted hull). 정점을 화면 픽셀 기준으로 부풀려(가까우면 굵고 멀면
  가늘게, 최소·최대 제한) 뒷면만 그린다. 법선은 겹친 위치끼리 평균낸 부드러운 법선이라 각진 조각에서도 선이 끊기지 않는다.
  · 붙박이 소품은 합치기 전에 사분면 넷으로 나눈 껍질 4개, 움직이는 소품은 방식별로 붙인다 —
    `rigid`(통째로 1개: 달력·인형·소화기·지구본·컴퓨터처럼 안쪽이 안 움직이는 소품), `parent`(관절별: 교사·시계), `mesh`(메시별: 문·액자).
  · 마루·벽·천장과 천(커튼)에는 붙이지 않는다.
- **조사 후광**: 가까이서 조사할 수 있는 물건을 가리키면 잉크 바깥에 노란 테두리가 숨 쉬듯 켜진다. 히트박스와 물체의 짝은
  위치로 정하고(`K.outline.bind`), 붙박이 물체의 후광 껍질은 처음 가리킬 때 만든다.
- 두 화면 스타일은 같은 모델링·같은 규칙을 쓴다. 다른 것은 재질·조명·윤곽선뿐이다(`K.isToon()` 한 곳에서 갈린다).

### 성능
- 사실적: 그리기 호출 ≈190, 프레임당 ≈28만 삼각형(시작 시점, 그림자 갱신 제외).
- 카툰: 시작 시점 그리기 호출 ≈230, 삼각형 ≈55만(윤곽선 껍질이 약 절반 — 붙박이 약 18만, 움직이는 소품 최대 약 13만).
  방 안쪽을 볼수록 사분면 컬링으로 줄어든다(호출 75~120, 36만~39만). 껍질은 그림자를 드리우지 않는다.
- **정적 병합**(`K.bakeStatic`): 움직이지 않는 소품을 재질·앞뒤 절반별로 합친다.
- **관 지오메트리**: 곡선에만 링을 촘촘히 둔다(직선 구간 링 낭비 제거 → 책상·의자 삼각형 43% 감소).
- **히트박스는 레이어 1**: 화면엔 안 그리고 레이캐스트만 받는다(핫스팟 60여 개의 드로콜 제거).
- **그림자 맵은 움직임이 있을 때만** 다시 그린다.
- 화질 단계: `desktop / mobile / low` (`?q=low` 로 강제). `K.detail` 이 곡면 분할 수를 줄이고,
  프레임이 모자라면 해상도(DPR)를 0.2씩 내린다.

## 옛 버전과 달라진 규칙

내용은 그대로지만 다음 둘은 바로잡았다.

1. **뒷문은 최종 이름을 맞힌 뒤에만 열린다.** 옛 버전은 처음부터 문에서 `0808` 을 입력하면 스테이지가 끝났다.
2. **일기·자료 종이와 액자는 마지막 단계와 클리어 뒤에도 만질 수 있다.** (옛 버전은 "마지막 조각을 교탁에서
   맞추세요"로 막았다.)

그 밖에 HUD 에 다음 할 일이 비어 있을 때 한 줄 안내를 넣었다(정답 단계·최종 단계·첫 일기).

## 내용 잠금과 수정 방법

`data.js` 의 내용은 `tests/model.test.mjs` 의 sha256 으로 잠겨 있다. 일부러 고쳤다면 테스트가 알려주는
새 해시로 바꾼다. 정답은 평문으로 두지 않고(`U()` 난독화) 테스트용 사본은 `tests/answers.mjs` 에만 있다.

## 알려진 한계

- 종단 검증(`e2e:stage1`, 검사 50개)은 카툰 화면에서 8챕터~엔딩~뒷문~이어하기까지 통과했다(2026-09-30, 재설계 뒤 기준).
  소프트웨어 렌더링(SwiftShader)으로 돌렸다.
- 윤곽선은 뒤집은 껍질이라 **평평한 면 위에 붙은 디테일**(사물함 문짝 등)은 선이 일부만 보인다. 커튼(천)에는
  선도 후광도 없다. 저녁·밤 색 변화는 카툰에서 사실적보다 은은하다.
- 교사 얼굴은 재설계에서 다시 만들었다(큰 눈·눈썹·움직이는 입·표정, [STAGE1_REDESIGN.md](STAGE1_REDESIGN.md)).
- 교실은 기억 소품 8개·스포츠 코너·AV 카트로 더 채웠다(재설계). 리빌 연출의 스쿼시&스트레치는 만들지 않았다.

- 화면 확인은 SwiftShader(소프트웨어 렌더링)로 했다. 실제 폰 GPU 에서의 프레임은 별도로 봐야 한다.
  느리면 `?q=low` 로 기준선을 잡을 수 있다.
- 교사 몸은 관절별 메시(약 45 드로)다. 필요하면 스키닝으로 합칠 수 있다.
- `assets/models` 와 `assets/vendor/GLTFLoader.js` 등은 스테이지 2 가 쓰므로 그대로 둔다. 스테이지 1 은
  더 이상 참조하지 않는다.
